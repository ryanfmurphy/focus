focus — code walkthrough

How the single-file macOS app in main.swift is put together.

1The mental model

A tiny state machine around “one current focus,” plus a SQLite log of everything.

State

Either a session is running (currentFocus != nil) or you're idle. That's it.

Three drivers

System events (login/wake/unlock), a 1-second timer, and menu clicks all read/mutate that state.

Three surfaces

Blocking modals, an always-on-top pill, and the 🎯 menu-bar item.

Every transition is written to ~/focus/focus.db.

3Startup — applicationDidFinishLaunching

  1. Set the 🎯 app icon (so modals aren't generic).
  2. Build the three surfaces: buildMainMenu() (an Edit menu so ⌘C/⌘V work in modals), buildStatusItem(), buildHUD().
  3. Register observers → all funnel into onReturn(reason): sessionDidBecomeActivedidWakecom.apple.screenIsUnlocked
  4. Start the 1-second uiTimer → tick(), added in .common run-loop mode.
  5. Call restoreOrPrompt() to handle a session left open from a previous run.
Why .common mode? A default-mode timer freezes while a menu or modal is open. Common mode keeps the pill countdown, the auto-proceed countdown, and the “Open for M:SS” timers all ticking.

4Storage — class DB

A thin wrapper over the SQLite C API. Conventions: strings bound with SQLITE_TRANSIENT (SQLite copies them), times stored as ISO-8601 UTC text, durations as integer seconds.

Two duration columns

seconds — planned duration, mutable (bumped by Add-time; overwritten with elapsed on interrupt/defer/early-complete).
original_seconds — stamped once at creation, never changes. Lets history show 9:12 / 25:00.

Tables

sessions, queue (ordered by a position column), time_additions (one per Add-time), preempts (one per pre-empt).

Status values completedinterrupteddeferredNULL = active

Idempotent migrations

exec() deliberately ignores errors — that's what lets every migration run on every launch and simply no-op once applied:

exec("ALTER TABLE sessions ADD COLUMN original_seconds INTEGER;")   // "duplicate column" after 1st run → ignored
exec("UPDATE sessions SET original_seconds = … WHERE original_seconds IS NULL AND …;")  // WHERE guard → no-op later
Load-bearing quirk: don't “fix” exec() to surface errors — the whole migration strategy depends on it swallowing them.

5A session's life

beginSession

Sets in-memory state, inserts the row (stamps both duration columns), logs start-popup time, pings Pushover, paints the pill.

tick() · 1 Hz

Computes remaining = deadline − now, updates the pill, and fires timeUp at zero. Drives display and detection.

timeUp

Chime + optional ping, then a mandatory rating (or hands-free auto-proceed), then chain to the next focus.

Wall-clock deadline. deadline is a Date (now + seconds), not a countdown integer — so sleep / lock / lid-close don't disturb the timer, and a resumed session computes the right remaining time automatically.

6The queue

A FIFO ordered by an explicit position column (not id), so it can be reordered.

  • enqueue appends at MAX(position)+1; enqueueFront inserts at MIN(position)−1.
  • reorderQueue(ids:) rewrites position = 0,1,2,… in one transaction (right-click Move up/down/to top/to bottom).
  • Delete via the Delete key, right-click Delete from queue, or when a session pops the front.
Lineage: original_session_id threads a task's root through the queue, so a deferred/pre-empted task's “(continued)” copy stays linked. COALESCE(original_session_id, id) groups a whole chain in history.

7Coming back & resume

onReturn(reason) funnels login/wake/unlock/launch: it debounces (10-second cooldown, since wake+unlock+session fire together), guards on showing, does nothing if a session is running, else prompts.

restoreOrPrompt (once at launch) recovers a session left open when the process died. If its deadline is still ahead, offerResume shows a three-button modal:

Resume

adopt the row back into memory and continue.

Pre-empt…

adopt it, then reuse changeFocus: remaining time → front, start new now.

Start fresh…

Abandon it, optionally clear the queue (confirmClearQueue()), then prompt for a new focus.

If the deadline already passed while away, it's adopted and tick() runs timeUp immediately.

8The modals — one shared shape

Every prompt is an application-modal NSAlert from makeAlert() (forces the 🎯 icon), floated above all Spaces.

  • Accessory views carry the text fields / checkboxes.
  • “Open for M:SS” — startElapsedTimer returns a .common-mode Timer and an openSeconds() closure read at close to log popup-open time.
  • Tab cycles fields via nextKeyView.
  • Inputs are minutes, converted to seconds (× 60) at the return; everything downstream is seconds.

11Gotchas worth remembering

  • Timers must be .common mode or they freeze under menus/modals.
  • Wall-clock deadlines (Date, not a counter) survive sleep/lock.
  • exec() ignoring errors is load-bearing for migrations.
  • seconds mutates; original_seconds is immutable. Old interrupted/deferred rows lost their true original (overwritten with elapsed), so they show —.
  • showing stops modals stacking; cooldown debounces return events.
  • One process, one DB, one user — no concurrency concerns.
